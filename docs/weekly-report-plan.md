# AI 주간보고서 백엔드 — 기획 (2026-11-23, 2판)

## 0. 한 줄

주간보고서 = **종목 섹션 여러 개**다. 백엔드는 지난주(월~금) 고른 종목마다 섹션 하나를 만든다.
- 주가·소식·메모 연결·지켜볼 것은 코드가 만든다.
- LLM은 섹션마다 흐름 2~3문장만 쓴다.
- 맨 위 종합(종목 칸, 합계, 이번 주 한눈에)은 **화면 코드가 섹션을 모아 계산**한다(이미 그렇게 되어 있음).
- 결과는 지금 화면 데이터 모양(`Studio.mock.ts`의 `ReportStock[]` + 머리 정보) 그대로 `studio_items.content`에 저장한다.

## 1. 지금 화면 (`ui/screens/studio/web/Report.tsx`, 앱 `app/Report.tsx`)

| 화면 부분 | 데이터 | 지금 누가 계산 |
|---|---|---|
| 머리: 몇 월 몇 주, 기간, 거래일 수, 종목 수, 작성 시각 | 보고서 머리 | 서버가 줄 값 |
| 머리: 종목 칸(등락률·작은 그래프·공시/뉴스 수), 공시 N건·뉴스 N건·메모와 연결 N개 | 섹션들 | **화면이 합산** |
| 이번 주 한눈에 | 섹션들의 등락률 | **화면 `reportSummary`가 숫자로 문장을 만든다** (예시 3종목일 때만 mock 문장) |
| 국내 증시 요약 (켰을 때) | 지수 3개 + 흐름 3줄 | 서버가 줄 값 (결정 1) |
| 종목 섹션 × N | `ReportStock` | 서버가 줄 값 |
| 맨 아래 안내 "투자 권유나 주가 예측이 아니에요" | 고정 | 화면 |

→ **요약용 LLM은 필요 없다.**

## 2. 종목 섹션 한 개 (`ReportStock`) 만드는 법

| 칸 | 만드는 곳 | 데이터·규칙 |
|---|---|---|
| `close` `pct` `prev` `closes[5]` `hi` `lo` `yr` `vol` | 코드 | `prices_daily`의 그 주 월~금과 지난주 마지막 거래일 종가. 휴장일이면 거래일만 쓴다 |
| `items` (공시·뉴스, 날짜, 출처) | 코드 | 3장 거르기 |
| `events` (검은 점) `counts` | 코드 | items의 요일 |
| `story` (흐름 2~3문장) | **LLM** 종목당 1번 | 입력: 주가 숫자 줄과 items. 소식이 0건이면 LLM 없이 코드 문장으로 쓴다 ("이번 주 새 공시·뉴스는 없었어요. …") |
| `memo` (내 메모와의 연결) | 코드 | 4장 |
| `watch` (앞으로 지켜볼 것) | 코드 | 가격 조건까지 거리, 정기 공시 일정, 소식 0건이면 "다음 주 새 공시·뉴스가 나오는지" |
| `own` (보유·관심) | 코드 | `user_stocks.status` |
| `logo` `logo_bg` `sc` `st` | **화면** | `lib/brandLogos` (서버에 색 칸이 없음) |

## 3. 소식 거르기 (가장 어려운 부분)

지난주 실제 데이터를 보면 종목에 붙은 뉴스가 많고 섞여 있다.
- SK하이닉스 515건, 삼성전자 633건
- KB금융은 쇼트트랙 같은 무관한 기사가 많다

1단계는 코드만으로 거른다(비용 0).
1. 제목이나 앞 150자에 회사 이름·별칭이 있는 기사만 남긴다 (`tracking_lexicon.yaml` 별칭, updates `news_require_company`와 같은 규칙).
2. 같은 사건 기사는 하나만 남긴다 (`news_clusters`).
3. 시황 묶음 기사는 제목 패턴으로 뺀다 ("[오전 시황]", "초고수들", "[특징주]" 묶음 등).
4. 종목당 뉴스는 최대 3건, `news_stocks.score` 높은 순으로 남긴다.
5. 공시는 그 주 접수분을 전부 넣는다. 단, 정정 공시는 원본과 합치고 첨부·자회사 공시는 뺀다(updates 규칙과 같게).

2단계(결과가 나쁘면): 관련성 판정 LLM(`gpt-6.1-terra`)을 붙인다.

## 4. 내 메모와의 연결

- 그 종목의 AI 연결 메모 중, **그 주에 나온 근거로 카드가 붙은 추적 항목**을 찾는다 (`tracking_updates`→`update_sources`의 뉴스 발행일·공시 접수일).
  - 카드 근거가 섹션 items에 없으면 items에 추가하고 번호를 단다.
- 서버는 `memo = {title, meta('11.10 작성 · AI 연결 중'), body, linked_count, memo_id}`를 준다.
- ⚠️ **화면을 고쳐야 한다.** 지금 화면 문장은 그 종목의 모든 소식 수(`counts.공시 + counts.뉴스`)를 센다. 서버가 주는 `linked_count`를 쓰게 한 줄 고친다.
- 메모가 여러 개면 카드가 붙은 메모를 먼저, 없으면 가장 최근 메모를 넣는다(화면 칸이 하나).
- 메모가 없으면 `memo`를 비운다. 화면은 이미 "메모 쓰기 ›"로 처리한다.

## 5. LLM (흐름 문장)

- 종목당 1번, 소식이 0건인 종목은 0번이다. 4종목이면 최대 4번이다.
- 검사는 기존 카드 검사(`pipelines/updates/checks.py`)를 다시 쓴다.
  - 숫자는 입력에 있는 것만
  - 금지 표현(권유·예측·평가)
  - 원인은 기사에 있을 때만
  - 실패하면 한 번 다시 부르고, 또 실패하면 코드 문장으로 대신한다
- 예시 화면 문장처럼 쓴다. 날짜·요일과 소식, 그날 종가 변화를 나란히 놓고 인과는 말하지 않는다.
  > "화요일(11.04) 신규 시설투자 공시가 나왔고, 다음 날(11.05) 종가는 전날보다 3.1% 높았어요."
  - 이 등락률도 코드가 계산해 입력에 넣는다.

## 6. 만드는 흐름

```
[앱] 종목 고르기 → POST /studio/reports {codes, market}
  → 크레딧 잔액 확인 (report 5)
  → studio_items 한 줄 (kind=report, trigger=request, status=generating, period=지난주 월~금, symbols=codes)
  → 백그라운드 생성 (종목 섹션을 차례로, LLM 최대 종목 수만큼)
     성공: status=ready, content={머리, market?, stocks:[섹션…]}, sources, 크레딧 5 차감(성공했을 때만)
     실패: status=failed, error (크레딧 안 씀)
[앱] GET /studio/items 로 상태 확인 (만드는 중 화면 → 완성되면 보고서)
```

- 프론트에서 바꿀 것
  - `startReport`: mock 타이머 대신 API를 부른다
  - 보고서 화면: 저장된 `content`를 읽고, 로고 색은 `brandLogos`로 채운다
  - 메모 문장: `linked_count`를 쓴다
  - 만들기 창의 종목별 "공시 1 · 뉴스 2" 미리 보기 → 7장 결정 3

## 7. 고려해야 할 점

### 데이터
1. **종목 시세가 하루 늦다.** `prices_daily`는 11-19까지 있고 11-20(금)이 없다. 지수(`market_indices`)는 11-20까지 있다.
   - 이대로면 지난주 보고서의 종목은 목요일 기준이 된다.
   - 수집이 밀린 건지 확인해야 한다.
   - 금요일 값이 없으면 마지막 거래일 기준으로 만들고 "11.19 종가 기준"이라고 적는다.
2. **"이번 주"의 정의.** 만들기 창은 "최근 5거래일"이라고 적혀 있다. 기획은 "가장 최근에 끝난 월~금"이다.
   - 수요일에 만들면 두 기준이 다르다.
   - 같은 주 다시 만들기·자동 생성과 맞추려면 월~금 고정이 낫다(창 문구도 바꿈).
3. **뉴스 품질.** 코드 거르기만으로 무관 기사가 남을 수 있다. 테스트 4종목으로 먼저 확인한다(KB금융이 시험대).
4. **공시 제목.** DART 제목은 "[기재정정]타법인주식및출자증권취득결정"처럼 딱딱하다. 화면 예시("신규 시설투자 결정")처럼 다듬을지 정해야 한다. 공시 종류별 표를 쓰면 코드로 할 수 있다.

### 비용·크레딧
5. LLM은 종목당 최대 1번이다. 종목이 많은 사용자(10종목 이상)는 만들기 창에서 고른 종목만 만든다. 크레딧은 종목 수와 상관없이 5로 할지 정한다.
6. 실패하면 크레딧을 쓰지 않는다. 일부 종목만 실패하면 그 종목은 코드 문장으로 채우고 성공으로 친다.

### 같은 주 다시 만들기
7. 같은 주·같은 종목 조합이 이미 있으면 새로 만들지 않고 그것을 연다(크레딧 안 씀).
   - 조합이 다르면 새로 만든다.
   - 메모를 새로 써서 다시 보고 싶은 경우는 일단 고려하지 않는다.

### 화면 맞추기
8. 메모 문장의 소식 수를 `linked_count`로 바꿔야 한다(4장).
9. 만들기 창의 종목별 "공시 1 · 뉴스 2"는 만들기 전에 보여 주는 숫자라, 미리 보기 API가 따로 필요하다. 1단계에서는 이 숫자를 빼는 걸 추천한다(결정 3).
10. 예시 3종목 고정 문장(`summary_default`)은 실제 모드에서 쓰지 않게 한다(`allDefault`가 mock 기준이다).

### 원칙
11. 흐름 문장은 사실을 나란히 놓기만 한다("공시가 나왔고, 다음 날 종가는 3.1% 높았어요"). "공시 덕분에 올랐어요"는 금지다. 검사에 이 규칙을 넣는다.
12. "앞으로 지켜볼 것"은 예측이 아니라 확인할 일정·조건만 쓴다("11월 말 분기보고서에 HBM 매출이 따로 나오는지"). 정기 공시 일정은 코드 규칙으로 만든다.

### 같이 일하기
13. 담당은 민성 님 혼자 (2026-11-23 결정). 스튜디오 화면은 상규 님이 만든 부분이라 화면을 크게 고칠 때는 알린다.

## 8. 만드는 순서

1. 섹션 만들기(코드만): 주가 계산, 소식 거르기, 메모 연결, 지켜볼 것 → 테스트 메모(사용자 2, `[리포트 테스트]`) 4종목으로 결과 JSON 확인
2. 흐름 문장 LLM, 검사, 대체 문장
3. API(`POST /studio/reports`), 백그라운드, 크레딧, 같은 주 처리
4. 프론트 연결 (startReport, 보고서 content, linked_count, 미리 보기 숫자 처리)
5. 평가: 4종목 × 2주 보고서를 사람이 확인 (숫자·출처·금지 표현·무관 기사)
6. (2단계) 국내 증시 흐름 3줄, 자동 주간 생성(토요일, `auto_report`), 관련성 판정 LLM, 공통 섹션 공유(사용자 늘면)
