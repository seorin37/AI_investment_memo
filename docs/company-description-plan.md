# 기업 개요(`stocks.description`) 채우기 기획 (초안)

작성: 이민성 · 2026-11-15 · 상태: **결정 대기**

## 1. 왜 하나

- 기업정보 페이지 맨 위 "기업 개요"가 `StockProfile.overview`를 그대로 보여 준다(`frontend/src/features/company/CompanyInfo.tsx`).
- 중앙 DB `stocks.description`은 **940곳 중 0곳**이 채워져 있다. 실데이터로 바꾸면 모든 회사가 빈칸이다.
- 목업 문구(`frontend/src/api/mock/seed.ts`)가 기대하는 모양은 이렇다.
  - 2~3문장, 120~200자
  - 해요체, 일반 투자자 눈높이
  - 무엇을 만드는지/파는지 + 실적이 무엇에 따라 움직이는지

## 2. 쓸 수 있는 원천 (중앙 DB, 2026-11-15 읽기 전용)

| 항목 | 결과 |
|---|---|
| 사업보고서 「II. 사업의 내용 > 1. 사업의 개요」 청크 | **825곳** (DART 기업 829곳 중) |
| 길이(최신 사업보고서 기준) | 10% 658자 · 중앙값 1,661자 · 90% 6,660자 |
| 공시가 없는 종목 | 114곳. 대부분 우선주(본주의 개요를 그대로 쓰면 된다) |
| DART 기업개황 API | 사업 설명 필드가 없다 |

원문의 모양:
- "당사는 …" 문어체이고, 종속회사 수·소재지·매출액 같은 숫자가 섞여 있다.
- 표로 시작하는 회사도 있다(예: HD현대중공업은 사업부문별 매출 표).
- 금융지주는 실적 설명이 길다(KB금융).

→ 앞 문장을 그대로 잘라 쓰면 목업 품질이 나오지 않는다.

## 3. 방법 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 규칙 추출 | 사업의 개요 앞 2~3문장 그대로 | 비용 0, 환각 없음 | "당사는", 숫자·표 섞임, 회사마다 품질 들쑥날쑥 |
| **B. LLM 요약 (추천)** | 사업의 개요(+「2. 주요 제품 및 서비스」 앞부분)를 넣고 2~3문장 요약 | 목업 수준 문장, 표도 처리 | 호출 비용, 사실 검증 필요 |
| C. 외부 기업개요(증권사·포털) | 가져와 저장 | 문장 품질 좋음 | 저작권·약관 문제(대표님 미팅: 저작권 주의) → 제외 |

B안 세부:
- 모델은 프로젝트 기본값 `gpt-4.1-mini`를 쓴다.
- 입력은 회사당 원문 최대 4,000자다. 829곳 1회 생성 비용은 1달러 안팎이다.
- 프롬프트 규칙:
  - 원문에 있는 사실만 쓴다.
  - 숫자(매출액·종속회사 수)·연도·전망·평가(유리/불리, 좋다/나쁘다)는 넣지 않는다. 숫자는 연도가 지나면 틀린 말이 되고, 평가는 기존 결정(LLM 답변 지침: 유리·불리 표시 X)과 충돌한다.
  - 해요체, 2~3문장, 200자 이하로 쓴다.
- 검증(로직): 길이, 숫자 포함 여부, "당사" 포함 여부, 회사명 포함 여부를 확인한다. 걸리면 1회 재생성하고, 그래도 실패하면 NULL로 둔다.

## 4. 저장 · 갱신

| 항목 | 추천 |
|---|---|
| 저장 위치 | `stocks.description`만 쓴다. **마이그레이션 없음**: 새 컬럼을 만들면 중앙 DB 버전 맞추기가 또 필요하다. |
| 출처 기록 | `data/company_descriptions/manifest.jsonl`에 symbol·rcept_no·모델·생성 시각·원문 해시를 남긴다. |
| 우선주 | 본주 개요를 복사한다(이름 끝 "우"·"우B" 등, 본주 매핑은 기존 우선주 처리 규칙 재사용). |
| 원천 없음(4곳) | NULL → 화면은 "기업 개요를 준비 중이에요." |
| 갱신 | 새 사업보고서(annual)가 들어오면 그 회사만 다시 만든다. 정기보고서 새벽 수집 뒤 단계로 연결한다. 정정 사업보고서는 원문 해시가 바뀔 때만 다시 만든다. |
| 일괄 명령 | `run_company_descriptions --symbols … --dry-run --limit N`. dry-run은 DB에 쓰지 않고 CSV로 결과만 낸다(검수용). |

stock_master 동기화 코드는 이미 "기존 description을 보존한다"고 되어 있어(`backend/pipelines/market/stock_master.py`) 충돌하지 않는다.
