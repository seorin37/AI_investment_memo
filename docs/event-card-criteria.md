# 수시공시 → AI 업데이트 카드 기준 (초안 v0.1, 2026-11-09)

수시공시(`disclosure_events`)가 들어왔을 때 **어떤 공시가, 어떤 메모에, 어떤 카드로** 이어지는지 정한다.
다음 단계인 "매일 도는 카드 실행기"의 입력 규칙이다. 확정 전 초안이며, 5절의 결정 사항을 팀에서 정한다.

## 0. 지금 상태와 왜 따로 정하나

- 지금 카드 경로는 **유사도 검색 하나**다. 추적 항목 임베딩 → 공시·뉴스 후보(수시공시 임계값 0.58 / 강한 후보 0.63) → LLM 카드 → 코드 검사 → 검수 호출 (`configs/updates.yaml`).
- 이 경로만으로는 두 가지가 빈다.
  1. **메모가 다루지 않은 중대 사건**: "삼성전자 HBM 납품 궁금"이라는 메모에 감자·관리종목 지정은 유사도가 낮아 카드가 안 나간다. 하지만 보유자라면 반드시 알아야 한다.
  2. **숫자가 핵심인 공시**: 잠정실적·배당은 `fields`에 정확한 숫자가 이미 있다. LLM이 문장으로 다시 쓰면 숫자 검사·검수 비용만 늘고 틀릴 위험이 생긴다.
- 그래서 **로직(규칙) 먼저, LLM은 보조**로 둔다 (10-23 대표님 미팅: 로직+LLM 병행, 기준점은 공시).

## 1. 대상과 공통 규칙

| 규칙 | 내용 | 근거 |
|---|---|---|
| 대상 메모 | 그 종목의 메모 중 AI 연결 ON인 메모 | 다음 단계 1순위와 같은 범위 |
| 종목 일치 | `disclosures.symbol` = 메모 종목. 자회사 공시(`is_subsidiary`)는 카드 X | 자회사 실적을 모회사 것처럼 쓰지 않게 (`recent.include_subsidiary: false`와 같은 원칙) |
| 1공시 1카드 | 같은 메모에 같은 접수번호 카드는 1장. 여러 추적 항목에 걸리면 한 장으로 합치고 항목을 모두 표시 | 알림 피로 |
| 상태 변화 때만 | 이미 카드로 알린 사건의 후속(정정 등)은 2절 정정 규칙만 따른다 | 가격 조건 카드 B안과 같은 원칙 |
| 파싱 상태 | `ok` → 규칙 카드 / `partial` → 값이 있는 필드만 쓰고 빈 칸은 "공시에 기재 없음"으로 / `failed` → 카드 X (다음 실행이 다시 받음) | 원문에 없는 숫자를 만들지 않음 |
| 시점 | 수시공시 수집(12:30·19:30) 직후 실행. 장중 공시는 12:30, 장 마감 후 공시는 19:30에 카드 | 수집 직후가 가장 빠름 |
| 문구 | 유리·불리, 매수·매도, 전망 표현 금지 (`banned`, `banned_patterns` 그대로) | 지침서 |

## 2. 공시 종류별 등급

최근 14영업일(10/21~11/09) 저장분 1,172건 기준 건수를 함께 적었다. 하루 평균 약 84건, 443개사.

### A등급 — 메모 내용과 상관없이 알림 (중대 사건)

메모에 그 주제가 없어도 보유·관심 종목이면 알아야 하는 사건. **고정 문구 카드**(LLM 없음).

| event_type | 건수 | 카드 조건 | 카드에 쓰는 필드 |
|---|---|---|---|
| insolvency (파산·회생·부도·영업정지·해산) | 2 | 항상 | 제목, 공시일 |
| trading_halt (매매거래정지) | 5 | 항상 | 제목, 공시일 |
| market_warning (관리종목·투자경고·위험 등) | 26 | 지정·해제 모두. 단 "투자유의안내"는 B등급 | 제목 |
| control_change (최대주주변경) | 7 | 항상 | 제목, 공시일 |
| capital_reduction (감자) | 0 | 항상 | 제목 |
| restructuring (합병·분할·주식교환) | 37 | 원본 공시만 (정정은 2절 규칙) | 제목, 상대 회사(있으면) |
| audit_report (감사보고서제출) | 2 | **감사의견이 적정이 아닐 때만** → 필드 추가 필요(5절) | 감사의견 |

### B등급 — 메모 주제와 맞을 때 알림

추적 항목의 주제가 공시 `topic`과 맞거나, 유사도 검색에서 이 공시가 후보로 걸렸을 때. **템플릿 문장 + 필드 숫자**로 쓰고, 템플릿이 없는 종류만 LLM 경로를 탄다.

| topic | event_type (건수) | 템플릿 핵심 (예) |
|---|---|---|
| earnings | prelim_earnings (279) | "3분기 영업이익 ○○억 원, 전년 같은 분기 대비 ○○% 증가/감소" — `op_income`, `op_income_prev_y`, `revenue` |
| earnings | earnings_change (4), earnings_guidance (10) | 변동 항목·비율 / 회사가 밝힌 전망 수치 (주체 "회사는 ~라고 밝혔어요") |
| shareholder_return | dividend (33) | "주당 ○○원 현금배당, 기준일 ○월 ○일" — `dps_common`, `record_date` |
| shareholder_return | treasury_buy (27), treasury_sell (15), share_cancel (46) | 주식 수·금액·기간 |
| shareholder_return | value_up (37) | 제목만 + 원문 링크 (본문이 길고 정형 필드 없음 → LLM 요약은 5절에서 결정) |
| business | supply_contract (133) | "○○ 공급계약 ○○억 원, 최근 매출 대비 ○○%" — `contract_amount`, `revenue_pct`, `counterparty` |

| capital | rights_offering (28), hybrid_bond (9), bonus_issue (1), share_count_change (3) | 신주 수·발행가·자금 용도 |
| risk | rumor_clarification (25), inquiry (8), lawsuit (16), operation_disruption (14), market_warning 중 투자유의안내 | 해명 내용 / 소송 금액·상대방 |

## 3. 정정공시

정정 제출본은 `is_correction=true`, 원본은 `corrects`로 연결된다(원본이 DB에 있을 때). 현재 정정 비율이 높다(공급계약 71/133, 지분투자 23/48, 합병 21/37).

- 원본 카드를 이미 보낸 경우: **카드에 쓴 필드가 바뀌었을 때만** "정정" 카드 1장. 문구는 "○○ 공시가 정정됐어요: 계약금액 ○○억 → ○○억 원".
- 카드에 쓴 필드가 그대로면(날짜·첨부 등 다른 칸만 정정) 카드 X.
- 원본 카드를 안 보냈으면 정정본을 새 공시처럼 1절·2절 규칙으로 처리.
- 원본이 DB에 없으면(`corrects` NULL, `correction.original_date`만) 새 공시처럼 처리.

## 4. 기존 유사도 경로와 합치는 법

1. 수시공시 수집이 끝나면 새로 들어온 `disclosure_events`를 읽는다.
2. A등급 → 그 종목 메모 전체에 고정 문구 카드.
3. B등급 → topic이 맞는 추적 항목이 있는 메모에 템플릿 카드.
4. 그 다음 기존 유사도 경로를 돈다. 이미 규칙 카드로 보낸 접수번호는 후보에서 뺀다(같은 공시로 카드 두 장 방지).
5. C등급과 템플릿이 없는 공시는 4번 경로에서만 근거로 쓰인다.

## 5. 정해야 할 것

| # | 질문 | 추천 |
|---|---|---|
| 1 | topic ↔ 추적 항목 주제를 어떻게 맞추나? 추적 항목에는 지금 topic 칸이 없다 | 항목 저장 시 판정 LLM이 6개 topic 중 하나를 같이 고르게 한다(호출 추가 없음) |
| 2 | A등급을 메모가 아니라 종목 단위로 보낼까? | 메모 단위 (화면이 메모보드 중심) |
| 3 | audit_report 감사의견 필드 추가 | `events_fields`에 `opinion` 규칙 추가 후 A등급 적용 |
| 4 | value_up·rumor_clarification처럼 서술형인 공시를 LLM으로 요약할까? | 1단계는 제목+링크, 반응 보고 2단계에서 LLM |
| 5 | supply_contract 최소 크기 | 코스피 공시 기준이 이미 매출 5% 이상이라 추가 기준 없이 시작 |
| 6 | 장 마감 후(19:30) 카드는 다음 날 아침에 묶어서 보낼까? | 첫 버전은 바로 저장, 알림 묶음은 앱 쪽에서 |
