# 뉴스 기능 변경 기록 및 팀 코드 리뷰 범위

개인 간 파일 전달·동일 이름 파일 교체 대신 Git 브랜치의 diff와 PR을 기준으로
검토한다. 공통 파일을 별도로 덮어쓰지 않는다. 뉴스 전용 브랜치는 dev를 기준으로
뉴스 관련 28개 파일을 분리한 변경이며, 이번 환경·문서 보완은 그 후속 변경이다.

## 기능 변경

| 범위 | 구현 내용 |
|---|---|
| RSS·네이버 수집 | 설정된 매체 RSS와 종목별 네이버 검색 보강, 중복 판별 및 종목 연결 |
| 실행기 | hourly 수집, 선택적 임베딩·반복, daily 처리, 발행시각 기준 기간 필터, 보관 정리 |
| 임베딩 | BGE-M3 dense/hybrid, 제목+요약 입력, 기존 variant 임베딩 제외 |
| 지정 ID 안전장치 | pending_articles와 embed_window의 선택적 news_ids, SQL 바인딩, 빈 목록은 조회 없이 0건 |
| 배치·오류 제어 | 내부·외부 batch_size 일치, 기본 16 유지, fail_fast=True이면 모델 오류 재시도 없이 중단 |
| 출력 검증 | 입력·출력 수 일치, dense 1024차원·유한값·0이 아닌 norm, hybrid sparse 검증 후 INSERT |
| 클러스터링 | 실제 L2 norm 코사인, complete-link, 기본 실험 임계값 0.65·24시간, 대표 기사·최소 유사도·누락 임베딩 보고 |
| 검색 평가 | Recall@k·MRR·nDCG, dense/sparse 가중치·정규화 비교 |

지정 ID에도 날짜·종목 조건이 적용되며 필요 시 include_untagged=True로
누락을 방지한다. 기존 (news_id, variant)는 재계산·덮어쓰기하지 않는다.
hybrid sparse가 None이면 오류이며 빈 사전은 유효하다.
함수의 사전 출력 검증과 DB 저장 트랜잭션은 구분해야 한다.
기존 pipeline은 autocommit을 사용하므로 전체 ROLLBACK이 필요한 실행은
호출자가 명시적 트랜잭션 및 저장 후 SELECT 검증을 구성해야 한다.

클러스터링은 독립적인 순수 함수 미리보기다. 기존 pipeline에서 자동 실행하지
않으며 DB 조회·저장 기능을 포함하지 않는다. 그룹 내 모든 쌍이 유사도·시간
조건을 만족해야 하므로 연결 사슬만으로 다른 사건을 합치지 않는다.

## 환경·문서 보완

- environment.yml의 Python 3.11과 기존 의존성 선언은 유지했다.
- 기존 환경 메타데이터를 참고해 feedparser==6.0.14, PyYAML==6.0.3,
  pytest==9.1.1을 추가했다.
- FlagEmbedding·torch·transformers는 기본 환경에 추가하지 않았다.
  README에 CPU/GPU 선택 설치 후보와 기존 환경 버전을 별도로 기록했다.
- 신규 환경 설치 성공은 미검증이다. 정적 버전·문법 확인이 설치 검증을
  대신하지 않는다. 전이 의존성을 고정한 잠금 파일도 아니다.
- README에서 코드 기본값(batch 16, FP16=False, fail_fast=False)과
  기존 GPU 실험 설정(batch 2, FP16=True, fail_fast=True)을 구분했다.
- 오프라인 모델 캐시 전제, dry-run의 외부 요청, 자동 정리와 DB 테스트의
  삭제 위험을 명시했다. 평가용 pipeline 예시는 --keep-days 0을 사용한다.
- .env와 비밀정보는 계속 출력·공유·커밋 금지다.

## 마이그레이션 및 데이터 보호

`alembic/versions/0006_news_embedding_variants.py`는 PR에 포함한다.
revision 0006은 0005를 선행하며 news_articles를 참조하는 임베딩 테이블과
인덱스를 생성한다. **공유 DB 적용은 팀 승인 후 별도 진행**한다.
코드 리뷰·PR 포함을 실제 마이그레이션 실행 승인으로 취급하지 않는다.

기본 보관 정책은 30일이다. hourly 반복은 하루 한 번, daily는 실행 시
종목·추적·업데이트 근거 연결이 없는 오래된 기사를 정리한다.
기사 삭제 시 임베딩도 ON DELETE CASCADE로 삭제된다.
평가용 데이터에는 --keep-days 0을 사용하되, 이 옵션은 다른 DB 쓰기를 막지 않는다.

DB 통합 테스트에는 DROP TABLE과 TRUNCATE ... CASCADE가 있다.
개발·공유 DB에서 실행하지 않는다. DB 이름의 test 포함 검사만으로 안전하지
않으며 격리된 폐기 가능한 DB와 별도 실행 승인이 필요하다.
전체 pytest 대신 검토된 순수 함수·mock 테스트만 명시적으로 선택한다.
